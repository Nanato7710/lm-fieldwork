# Tokenization primer

このページは、言語処理100本ノックの問49を読む前の10〜15分の足場です。
ここでは仕組みを暗記せず、文章がモデルへ渡るまでの入口だけを追います。

## 文章はそのままモデルへ入らない

たとえば、次の文章を考えます。

```text
学生は短い文章を読んだ。
```

文字ごとに分けるなら、先頭は `学 / 生 / は / 短 / い / ...` となります。
人が単語らしいまとまりを考えるなら、`学生 / は / 短い / 文章 / を / 読んだ / 。` のような案もあります。
実際のLLM用tokenizerは、語彙に応じて文字、単語の一部、記号などを組み合わせます。

ここで重要なのは、tokenが必ずしも単語ではなく、同じ文章でもtokenizerによって分け方が変わることです。
特に日本語には英語の空白に相当する明示的な区切りがないため、分割方法を一つに決められません。
LLMのtokenizationと、言語学的な単語境界を求める形態素解析は目的が同じではありません。

## モデルへ渡るまで

```text
text
  ↓ tokenizer が分割する
tokens
  ↓ vocabulary で番号を引く
token IDs
  ↓ model へ渡す
```

- **token**: tokenizerが文章を分けた単位。
- **tokenizer**: textとtoken IDsの間を変換する処理。
- **vocabulary**: tokenと整数IDの対応表。
- **token ID**: vocabulary内のtokenを表す整数。
- **encode / decode**: textをtoken IDsへ変える処理と、その逆方向の処理。

ここではBPEなどの作り方までは扱いません。
tokenizerの学習方法と語彙サイズの比較はWeek 2で扱います。
